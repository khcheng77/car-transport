1. 背景與目標

系統目前有四種申請：巡迴物品轉運申請（巡迴物品轉運作業）、院區物品轉運申請（院區物品轉運作業）、差旅共乘申請（差旅共乘作業）、一般用車（一般用車申請作業，含例行用車類別）。 業務單位反映申請項目太多，使用者常不知道該選哪一個，選錯後才被駁回或轉單，徒增往返。

本單元的目標：使用者照著畫面填寫自己的需求資料，畫面依填寫內容自動長出需要的卡片， 系統同時依這些資料判定該用哪一種申請，最後一鍵前往該功能，已填的資料自動帶入；每次引導都留下紀錄，可回頭查看與修改。

2. 單元定位與範疇

本單元負責本單元不負責
一張需求表單，依填寫內容顯示或隱藏後續卡片建立或送出任何申請單（一律在目標功能內送出）

3. 設計原則

  1. 填的是資料，不是回答問題。畫面上沒有「您要做什麼？」式的問句；使用者填的每一格都是真正要送出的申請資料，判定流程的同時也在收集帶入資料。
  2. 流程靠卡片出現來呈現。前一張卡片的關鍵欄位填好，下一張需要的卡片才出現；不需要的卡片不出現。
  3. 判定結果看得見。表單最下方固定一張「判定結果」卡片，隨填寫即時更新：將使用哪一項申請、為什麼、還缺哪些欄位。
  4. 只分流、不送單。送出一律在目標功能完成，驗證與業務規則只維護一份。
  5. 只收共用、易填的資料。各功能專屬的欄位留在原表單填寫，避免同一套欄位在兩處維護。
  6. 畫面結構與其他單元一致。首頁是查詢條件＋清單，「＋ 新增」進入表單，「細節」看歷史資料（依 UI 規範的三畫面子流程）。
  7. 規則以資料維護。「卡片出現規則」與「判定決策表」都寫成資料表，規則異動只改表，並以測試保護每一條路徑。

5. 使用流程

① 首頁按「＋ 新增」進入引導表單；申請人、部門、分機預帶登入者

③ 判定結果即時更新顯示將使用的申請、理由與缺少的欄位

⑤ 補齊後送出在目標功能補專屬欄位、送出；紀錄回填申請單號

7. 判定決策表

判定只看欄位值，依序比對，第一條符合的規則即為結果。用車天數只用於顯示與提示，不參與判定。

規則條件（欄位值）導向判定結果卡片的理由文字
R2運送內容＝只有物品，且寄件據點≠收件據點B 院區物品轉運申請寄件與收件在不同據點，由院區物品轉運車沿線收送，需經二級審（單位主管審核）後由調度派車。
R6運送內容＝只有物品，寄件據點＝收件據點，且危險品運輸＝是 v2.11B 院區物品轉運申請危險品運輸，不走院區內巡迴班次，改由院區物品轉運派車，需經二級審（單位主管審核）後由調度派車。
R7運送內容＝只有物品，寄件據點＝收件據點，危險品運輸＝否，且貨物清單合計體積或合計重量未小於收貨日巡迴車上限（含任一件單件超過） v2.11B 院區物品轉運申請貨物合計 ○L／○kg 未小於收貨日巡迴車上限（或「某物品」單件超過上限），改由院區物品轉運派車，需經二級審後由調度派車。
R1運送內容＝只有物品，寄件據點＝收件據點，危險品運輸＝否，且貨物清單合計體積與合計重量皆小於收貨日巡迴車上限 v2.11 加條件A 巡迴物品轉運申請寄件與收件在同一個據點、非危險品，貨物合計小於收貨日巡迴車上限，由院區內固定班次巡迴收送，送出即自動排入最近班次。
R3（原：有人搭車，且期間 ≥ 30 天 → 例行用車）v2 移除例行用車併入一般用車，時長不分類別。
R4運送內容＝有人搭車，出發地∈共乘出發地清單，目的地∈共乘目的地清單，且（隨行物品＝沒有，或隨行物品＝有且屬於隨身物品＝是） v2.11 加條件C 差旅共乘申請往返共乘清單內的地點且未攜帶物品（或只有隨身物品），由系統自動併車共乘。
R5運送內容＝有人搭車，且（出發地或目的地＝其他地點，或隨行物品＝有且屬於隨身物品＝否）D 一般用車地點不在共乘清單或隨行物品不屬於隨身物品，由調度人工確認資源後派車，可自駕。

未判定的情況（v2.11）：寄件與收件同據點但未選危險品運輸、地點都在共乘清單且隨行物品＝有但未選是否屬於隨身物品時，判定結果卡片提示先選擇，不導向任何申請。

收貨日巡迴車上限怎麼算（R1／R7，v2.11）：巡迴車＝寄件據點在希望收貨日期當天各班次使用的車輛（含調度對該日車次改派的車輛），任一台放得下即可。貨物合計體積＝Σ（長×寬×高×件數），以公升計、不含浪費係數；合計重量＝Σ（單件重×件數）。兩者都要小於該車容量與載重才導向 A，等於上限也導向 B。單件超過上限時合計必然超過，理由文字會指出是哪一件物品。判定結果卡片列出合計與上限數字；貨物清單隨時增減，判定即時更新。

例行用車怎麼走：總經理、部長秘書的用車需求同樣經 R4／R5 判定；導向一般用車後，在一般用車新增畫面把「用車類別」改成「例行用車」即可（該選項只有這兩種角色看得到）。引導本身不設定類別，帶入時一律為「一般用車」。

需要業務單位確認：R4／R5 以「地點是否在共乘清單、隨行物品是否屬於隨身物品」劃分 C 與 D（v2.11 已定案，見第 15 節事項 1）。長天數（例如數個月）且兩地都在共乘清單、無隨行物品時，依規則仍導向 C，見待決事項 2。

10. 跳轉與帶入機制

  1. 按下「前往並帶入」時：建立（或更新）引導紀錄，只把目前顯示中的卡片的資料整理成帶入資料，寫到目標單元狀態的 prefill，將目標單元切到「新增」畫面，再以 goto() 跳轉。
  2. 目標單元的新增畫面依序採用：申請中（暫存／撤回修改）的單 → 引導帶入資料 → 系統預設值。
  3. 帶入資料只使用一次，畫面產生後即清除；之後從清單按「＋ 新增」不會再出現舊資料。
  4. 目標畫面頂部顯示「已由申請引導 GD-xxxx 帶入：…，其餘欄位請補齊並確認後送出」與「← 回到引導修改」；有危險品時一併提示。
  5. 「← 回到引導修改」會重新打開同一筆引導紀錄的填寫內容，卡片與已填資料維持原樣。
  6. 在目標功能送出成功後（直接送出，或先「暫存」為申請中、之後再從明細／編輯畫面送出），引導紀錄自動回填申請單號；送出仍走目標功能自己的驗證與確認視窗，引導本身不建立、不送出任何申請單。

長期用車（數週～數個月）不再另走例行用車；依 R4／R5 判定。導向一般用車時，一般用車本身支援數小時～數個月。
總經理／部長秘書要申請例行用車照常引導；導向一般用車後，在一般用車畫面把「用車類別」改為「例行用車」（只有這兩種角色看得到此選項）。
需要管制區通行證、會進入台北市、要加班引導不收集；導向一般用車後在其新增畫面勾選。通行證會影響調度可選的車輛，不影響判定。
只有物品、同據點、危險品運輸＝是導向 B（R6）；院區物品轉運申請的「危險品運輸」帶入「是」，判定結果與目標畫面提示「調度派車時只能使用可載危險品的車輛」。v2.15
只有物品、不同據點、含危險品照舊導向 B（R2），同樣帶入「危險品運輸＝是」並提示同上；危險品運輸不影響判定。

14. 驗收條件

  • 判定測試：R1、R2、R4、R5、R6、R7 每條規則（含危險品運輸、巡迴車上限的合計與單件、等於上限、依收貨日改派車輛；隨行物品屬於隨身物品是／否），以欄位值輸入 Guide.route(表單值) 皆得到正確功能；判定功能不含例行用車；長天數（例如 92 天）依地點與物品判定為 C 或 D。
  • 卡片測試：卡片顯示與否完全符合第 6.2 節條件表（Guide.visibleCards(表單值)），不論天數都不出現 K5。
  • 帶入測試：C、D 的帶入資料能直接通過該功能驗證（含多天一般用車）；A、B 的據點、日期時間、貨物正確出現在新增畫面。
  • 只帶入可見卡片：先填 K6 再把運送內容改為「只有物品」，K6 的資料不得被帶入 A／B。
  • 引導紀錄：前往並帶入建立紀錄；回到引導修改後重新帶入更新同一筆並記錄改判；目標功能送出後回填單號；已送出的紀錄不可再修改，重新帶入另建新紀錄。
  • 只用一次、可返回、不送單：跳轉後從清單按「＋ 新增」不再出現帶入資料；未在目標功能送出時，系統不新增任何申請單。
  • 符合 UI 規範：三畫面切換正常；卡片、欄位、單選膠囊與既有單元一致；開啟時無錯誤訊息；node tests/guardrails.test.js 全數通過（目前原型 228 項）。

15. 待業務單位決定事項

1. 差旅共乘申請（C）與一般用車（D）以欄位劃分是否可行？
v2.11 定案 出發地與目的地都在共乘清單內，且沒有隨行物品或隨行物品屬於隨身物品 → C；選了「其他地點」，或隨行物品不屬於隨身物品 → D。
差旅共乘申請靠系統自動併車，地點必須在清單內、不處理貨物；一般用車由調度人工派車，可自駕、可帶貨、地點不限。
2. 長天數但兩地都在共乘清單、無物品時，仍導向差旅共乘申請嗎？
先依 R4 導向差旅共乘申請；若業務認為長期用車都應走一般用車，可加一條天數門檻規則（例如 ≥ N 天 → D），只改決策表。
移除例行用車後，原本 30 天以上的需求會依地點分流；差旅共乘申請是以單趟／來回媒合為主，是否適合多週行程需業務確認。
3. 引導是否要替有權限者預設「例行用車」類別？
不預設，帶入一律為「一般用車」，由使用者在一般用車畫面自行切換。
例行用車是身分特權而非流程差異（一般用車 v2 §2.1）；引導只判定走哪一種申請，不替使用者決定是否動用優先權。
4. 引導是唯一入口，還是新增的入口？
第一階段為新增入口，四個申請項目照樣保留；觀察使用情況後再決定是否對一般使用者隱藏。
熟悉流程的使用者直接點進去比較快；先並存可降低導入風險。
5. 只有物品、但含危險品時導向哪裡？
v2.11 定案 物品寄送新增「危險品運輸」：同據點且危險品運輸＝是 → B（R6）；不同據點照舊 → B。導向後仍提示於備註說明、聯絡調度；A／B 是否新增危險品欄位另案評估。
一般用車規格明訂「必有人隨行、純載貨走運輸申請」，因此不能導到 D。
6. 引導紀錄要保存多久、誰看得到？
比照各申請單的保存期限；一般使用者只看自己的紀錄，業務單位可查全部（供分析使用者常走的路徑）。
原型的紀錄存在瀏覽器記憶體，重新整理即清空；正式版需落資料庫並決定權限。
7. 是否一併提供「我的所有申請」跨模組查詢？
列為另案。引導紀錄已能從申請單號跳到各申請明細，可作為過渡。
送出後使用者會想在同一處看進度；它與引導互不相依，分開做可縮短時程。
