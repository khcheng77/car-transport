## A 區域內物流（moduleA.js）

### A-1　修正：期望收貨時間誤實作為硬性截止 ✅
- **現況**：deliverTime 被當成 deadline，到站 > deadline 直接跳過班次；全跳過回 `late`，單停在 unscheduled。
- **規格 4.1**：期望時間只影響**挑選班次**——找當天經過該站、到站時間與期望時間差最小的班次（提早/延後兩方向都比）。塞不下才順延，沒有「來不及就整張退件」。
- **要改成**：移除 deadline 硬性跳過；exact 模式依 `|到站−期望|` 升冪逐一試裝，第一個裝得下即排入（不論早晚）；移除 `late` 原因碼，失敗只剩 `toobig` / `full`；期望與實際到站差值回傳前端顯示（「較期望時間晚 X 分」），不作為成敗依據。
- **驗收**：填早於當日首班到站的期望時間，仍應排入首班並提示時間差，不得回 late。

### A-2　修正：站內未實作「先卸後裝」與重量增減 ✅
- **現況**：startLoad 逐站累計只加不減，容量單向被佔用。
- **規格 3.4/3.5**：同趟允許送收混合，同站固定順序**先卸貨（釋放容量）→ 再裝貨**；重量逐站累計，卸扣收加。
- **要改成**：車輛負載改**動態淨值**，區分「本站要卸」與「本站要裝」；到站先卸（有效體積、重量、**地板投影 floor** 同步釋放）再對收貨單跑 checkLoad；站內時間額度不受影響（卸與裝的 handleMin 都計入該站佔用）。
- **備註**：B 已有動態淨值寫法（netVol -= eff），沿用同一套。

### A-3　補上：駕駛異常回報完整流程與自動寄信〔雛形後補〕⏸
- 駕駛整趟跑完回總部後回報，只標異常站點（正常站免確認）；原因二選一：不準時／沒出現。
- 標記站點後列該站當班對應申請單清單，駕駛勾選出狀況的單（可多張）。
- 記錄到申請單層級存檔備查；**立即**觸發自動寄信（非批次），一單一信，收件人＝申請人＋直屬主管（沿用審批對應，不另建表）。
- **待業務確認**：通知信格式（至少含站點/原因/日期）。

### A-4　補上：指定期望時間需可選日期 ✅
- 申請單新增 `serviceDate`（排班日期）：`exact` 模式可選**今天或未來日期**（表單 `min=今天`、送出再驗一次）；`asap` 即當天。
- **容量與站內額度僅在同一日期的單之間競用**——不同日期各自獨立計算（否則日期功能會算錯）。
- 查詢清單、明細、車次追蹤皆顯示日期；司機任務單改以「日期＋班次」為一張任務單。

### A-5　補上：今天已過的時間不可媒合 ✅
- 媒合引入「現在」：`ModuleA.now()`（可注入，供測試固定時點）。
- 日期為今天時，車輛**抵達收貨站**的時間 `≤ 現在` 之班次一律不採計（車已離開、無法上貨）；未來日期不受限。
- 新增失敗原因 `past`：指定日期早於今天，或今日班次皆已出發 → 提示改指定未來日期（不自動排隔日，維持 G12）。

### A-6　修正：班次過少 ✅
- `regionalShifts` 由 3 班改為**每日 5 班**（08:00 / 10:30 / 13:00 / 15:00 / 17:00），兩台車輪替。

## B 跨據點南北幹線（moduleB.js）

### B-1　修正：出發據點寫死在最北端 D10 ✅（基地已設 D9 龍潭；北側排班待業務）
- **現況**：southboundFrom(D10) 起算、回程固定回 D10。
- **規格**：出發據點為桃園龍潭一類**中間位置**。
- **已改成**：出發據點改主檔參數 `DB.homeSite`，**現值＝`D9` 桃園龍潭**（依規格背景之中段位置）；去/回程方向與行經序列由 homeSite 在南北順序表位置推算；回程終點回 homeSite（2.7 不變），並於抵達終點時卸下以基地為迄點的貨。
- **北側據點現行處置（暫定，待業務確認後調整）**：現行車次模型為「自基地南下 → 折返北上回基地」，D10 台北位於基地以北、不在任何路線上。程式以 `isServable(o)` 判定，涉及北側據點（收貨或送貨）的託運單**一律不排入**，並在派車 trace 與調度室待派清單標示「基地以北・待確認」與原因——**不靜默載走**（否則會出現載上車卻無法卸貨的單）。
- **待業務確認**：基地在中段時，**北側據點如何排班**（同趟先北後南？另立北向車次？北側改由其他基地服務？）。決定後只需放寬 `isServable` 與路線序列產生方式。

### B-2　移除：accepted 狀態與 leg 欄位 ✅

- 所有 `leg === 'outbound'` 過濾改為方向判斷。

### B-3　修正：天數對照表未接上時間上限 ✅（查表架構完成，數值走主檔）

- **相依**：對照表實際數值待業務提供（先做查表架構、數值走主檔）。

### B-4　修正：決策矩陣缺去程兩列 ✅

### B-5　補上：回程全域直達的「撞期」判定 ✅（窗寬待業務確認）

### C-4　補上：調度室確認步驟與人工覆寫紀錄 ✅

## 跨模組注意事項

1. **架構落差**：現行為 js/ 前端原型；規格 1.5/2.3 定案 C#/.NET Framework 4.8 MVC、係數 Provider static 單例不用 DI、自行讀連線字串、不需獨立 API 層、Repository 不做鎖定/交易隔離。轉正式實作時逐條對回。
2. **裝載引擎共用**：loadengine 由 A、B 共用；B 刻意只跑 Level 1＋重量（已回填幹線規格 2.10）。動態淨值釋放容量的邏輯兩模組須行為一致。
3. **示意數值**：12 分/站、55 分/段、40 分站內額度、浪費係數、形狀懲罰門檻、15 分緩衝等皆示意值；一律走主檔/設定檔，不寫死，待業務確認後替換。
